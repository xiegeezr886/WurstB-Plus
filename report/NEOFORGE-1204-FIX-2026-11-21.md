# Simply NeoForged 1.20.4：锁定 NeoForge 20.4.248 的安全对照

**决定：不改正式包最低运行时声明。** 2026-11-21 在同一锁定整合包上，只保留界面访问器和测试入口的 QA 副本，将最低声明从 `[20.4.251,)` 改为 `[20.4.248,)` 后成功进入单人世界，停服后完成保存，进程自行退出 `0`。严格组被同一加载器按预期拒载。这个差异证明了**安全子集的最低版本门槛**，不能证明被移除的正式初始化、Mixin 和依赖在 `.248` 上兼容。源码 `neo_version_range=[20.4.251,)`、构建用的 `neo_version=20.4.251` 和 `neoforge_version=20.4.251` 全部保留。

**追加结论：原入口安全副本也通过 `.248` 两轮单人实机验证。** 同一测试存档完成保存、重启读回、再次保存。两轮均命中原 GUI 和世界渲染链、完成三个维度保存并自然退出 `0`。这是原入口与保留方法的证据，不是未裁剪正式包通过；未修改正式门槛，也未使用 `.251` 替代对照。详见下文“原入口两轮实测”。

**执行了什么。** `WurstForgeInitializer`、`EventManager`、`IngameHUD`、`RenderScope`、`GlStateGuard` 等共 14 个类与发布物逐字节一致。`WurstClient` 是裁剪类，不是整类复用；其保留的 15 个方法逐一比较规范化 JVM 指令，含操作数、调用目标和跳转，不比较常量池编号与调试信息；`initialize()`、`shutdown()` 等全部一致。[归档逐项摘要](../neoforge/versions/1.20.4/build/q1121/entry/a2/archive.json) · [方法比对](../neoforge/versions/1.20.4/build/q1121/entry/methods-verified.txt)

**安全边界与未覆盖部分。** 普通非管理员账号、无网络能力的 AppContainer、离线身份、禁用多人和聊天，仅打开单人副本；两次进程在恢复执行前均核验令牌。宿主在探针前后能连接本机监听端口，同一 Java 在隔离身份下超时，监听端未收到连接。[隔离记录](../neoforge/versions/1.20.4/build/q1121/entry/a2/isolation.json)。QA JAR 从空归档白名单生成：没有 `ForceOpHack`，没有真实的功能注册表、命令执行、插件发现、测试控制端口、SeedCracker、Baritone 或内嵌依赖。相关类名仅在需要满足原方法签名时由[无功能占位](../neoforge/versions/1.20.4/build/q1121/entry/a2/selection.txt)提供；少数占位只记录调用栈。Minecraft 仅加空标记接口以满足原初始化的类型检查。控制台中的 `renderFinders` 不代表执行了搜索；HUD 命中了无可见控件的分支，不代表绘制了 NanoVG 控件。文件保存、渲染入口与关闭调度已实测，所剔除的功能及其清理实现未测。此前[原包及正式包对照](NEOFORGE-120x-QA-2026-11-21.md)仍是独立记录。
