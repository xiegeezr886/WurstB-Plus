# WindowsDuo GUI 开合动画

Fabric 1.20.1 的 CGUI 与导航器共用 `DuoGlassTransition`。来源为
[kaedeharakazuha1029/windowsduo](https://github.com/kaedeharakazuha1029/windowsduo)，
固定提交 `69dab2ceaf17255643848856ba58140cdee3dc26`；本地只读参考位于
`reference/clients/windowsduo`，MIT 许可与来源声明随资源打包。

从 `win/glass_overlay.py` 的 FS_DUO 移植底边铰链逆投影、Vogel 盘采样、
mip LOD、边缘覆盖衰减及玻璃吸光。参数沿用最大倾角 88°、眼距为高度的两倍、
扩散系数 0.42、暗化系数 0.001；采样由上游最多 32 次降为最多 12 次。CGUI 以界面底边为铰链，
导航器以面板底边为铰链。原先的缩放开合已替换。

角度平滑沿用每帧趋近 22%，换算为按时间计算的 60 Hz 等效值，避免不同帧率
改变动画速度；约 360ms 收敛。打开途中关闭保留当前角度。完全收起前淡出
剩余底边；界面之外透明合成，保留游戏画面，不生成原桌面版本的黑色遮罩。

GUI 图层在每段开合开始时缓存一次，采样纹理最高 1280×720 并生成 mip；
玻璃模糊在最高 960×540 上运行，再单次线性采样合成到原生分辨率。
两个界面共享有界纹理、着色器和 VAO 缓存，避免每次打开重新编译和分配；
窗口移除时清除图层有效标记，尺寸变化时重建。动画结束后直接使用普通 GUI
渲染，不运行折叠着色器。着色器不可用时退回常规界面。

导航器常驻渲染使用原生分辨率 NanoVG 抗锯齿，取消全屏 1.5 倍超采样；
外阴影从 19 层路径合并为一次盒状渐变。可见卡片文本最多每 250ms 重新测量，
屏外设置不重排，关闭的卡片不遍历设置树。背景模糊限制到 640×360、30Hz，
GUI 交互仍随游戏帧率绘制。布局、配色、分类和展开控件沿用已有实现。
开合期间阻止控件点击、拖动、滚动和输入，Escape 可提前关闭。
CGUI 与导航器的快捷键关闭均调用 `onClose()`，避免绕过动画。

`DuoGlassMotionTest` 验证终点、打开途中反向与帧率无关性。
现有开发测试接口 `/screen?name=close` 调用当前屏幕的 `onClose()` 生命周期，
用于验证关闭动画；不生成键盘或鼠标输入。

验证：完整测试集 47 项通过。独立 Java 17 / Fabric 1.20.1 客户端已检查
两个界面的打开、完全展开与关闭画面，未发现着色器编译或 GL 报错。
性能优化后，Intel RaptorLake-S 核显测试客户端打开导航器的五次每秒 FPS
采样为 106、81、84、83、76（原版 Minecraft FPS 计数，非伪装 HUD）。
该采样反映测试世界与当时窗口环境，不代表所有世界的固定帧率。
截图位于本地 `.dsh-tmp/duo-*.png`，不打包。最后一次关闭截图采集前
测试客户端已正常退出；优化后关闭过程未重新截图。
